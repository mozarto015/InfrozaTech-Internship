# Task 4: Background Job & Notification Service

A Node.js backend service that queues notification jobs, processes them asynchronously using BullMQ and Redis-compatible Memurai, retries failed jobs automatically, and provides an API to check job status.

## Features

- **REST API:** Accept notification requests through Express.js.
- **Background processing:** Process jobs asynchronously using BullMQ.
- **Redis integration:** Store and manage jobs using Redis/Memurai.
- **Automatic retries:** Retry failed jobs up to 3 attempts using exponential backoff.
- **Job status tracking:** Check whether a job is waiting, active, completed, or failed.
- **Error handling:** Return appropriate HTTP status codes and error messages.
- **Testable API:** Test endpoints using Postman.

## Installation and Setup

### 1. Install dependencies

Open a terminal inside the project folder and run:

```bash
npm install
```

### 2. Start Redis/Memurai

Ensure your Redis-compatible service is running on:

```text
127.0.0.1:6379
```

### 3. Start the API server

Open the first terminal and run:

```bash
npm run dev
```

The server should run at:

```text
http://localhost:3000
```

### 4. Start the background worker

Open a second terminal in the same project folder and run:

```bash
node worker.js
```

Keep both the API server and worker running while testing.

## API Endpoints

### 1. Queue a notification

**Method:** `POST`

**Endpoint:**

```text
http://localhost:3000/notify
```

**Request body — JSON:**

```json
{
  "message": "Hello, this is my first background job!"
}
```

**Expected response:** HTTP `202 Accepted`

```json
{
  "success": true,
  "message": "Notification job queued successfully.",
  "jobId": "1"
}
```

The job ID is generated by the queue and may differ.

### 2. Check job status

**Method:** `GET`

**Endpoint:**

```text
http://localhost:3000/notify/1
```

Replace `1` with the actual job ID returned by the POST endpoint.

**Example response:**

```json
{
  "success": true,
  "jobId": "1",
  "state": "completed",
  "message": "Hello, this is my first background job!",
  "result": {
    "delivered": true,
    "message": "Hello, this is my first background job!"
  },
  "failedReason": null
}
```

The result depends on the job's actual state. A nonexistent job returns HTTP `404 Not Found`.

## Retry Logic

The notification queue uses the following retry configuration:

```javascript
{
  attempts: 3,
  backoff: {
    type: "exponential",
    delay: 1000
  },
  removeOnComplete: false,
  removeOnFail: false
}
```

If a job fails, BullMQ retries it up to three attempts in total, with an increasing delay between attempts. Completed and failed jobs are retained so their status can be checked.
